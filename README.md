# Кварта: лендинг обжарки с формой заявки

Тестовое задание. Сайт: https://kvarta.onrender.com · репозиторий: https://github.com/BrigAlen/kvarta · журнал ошибок ИИ: `NOTES.md`.

## Стек
Next.js 16 (App Router) и TypeScript, CSS Modules, без UI-библиотек. Зависимости: `next`, `react`, `pg`. Хостинг Render (free, Франкфурт), база Neon Postgres (Франкфурт). Форма шлёт `POST /api/lead`, заявка сохраняется в Postgres, уведомление уходит в Telegram.

## Что делал я
- Выбрал стек и хостинг. Vercel не прошёл верификацию по телефону с белорусским номером — перешёл на Render + Neon (Франкфурт), засыпание бесплатного Render закрыл пингером UptimeRobot.
- Настроил агента: CLAUDE.md с правилами и скилл kvarta-step — цикл «план → подтверждение → код → проверка → коммит → журнал», критерии готовности для каждого шага.
- Вёл дизайн: отклонил первый вариант (оранжевый + кобальт, ячейки в рамках — выглядело дёшево), выбрал шрифты и направление, заметил висящие предлоги и тире в начале строки, пустой десктоп, пачку-SVG, которая не читалась как пачка, и общее «несовременно» — после этого переписал своё же правило про градиенты: разрешены как переходы, запрещены как декор.
- Подобрал фото на Unsplash, отсеял кадры с чужими брендами и штампами (латте-арт, дымящаяся чашка).
- Добавил то, чего не было в ТЗ: согласие на обработку персональных данных и страницу политики (закон РБ № 99-З). Я не юрист — для реального клиента текст должен проверить юрист и нужен e-mail.
- Задал поведение поля телефона без жёсткой маски.
- Создал Telegram-бота для уведомлений о заявках.
- Использовал второго Claude в браузере как независимого ревьюера и отфильтровал его советы: не менять «1–3 день» (факт брифа), не выдумывать скидку для подписки, не выдавать сток за основателей, не добавлять несуществующие контакты.
- Миграции на прод применял сам — строку подключения прода агенту не передавал.

## Что делал ИИ и где ошибся
Код, тесты, проверки в Chrome, документы. Ошибки (полностью в `NOTES.md`): висячие предлоги и десктоп проверен не сразу; регулярка с обратным слешем ломалась при записи файла (дважды, поймал тест); пачка не читалась как пачка; неверное имя колонки в проверочном запросе; курсор в поле телефона. Самая заметная: я запушил код, которому нужны новые колонки, не дождавшись подтверждения миграции, и прод-форма отвечала 500, пока миграцию не применили. Правило на будущее: пуш со сменой схемы только после подтверждения миграции.

## Допущения
- Телефона и Instagram мастерской в брифе нет, на сайте их нет: связь через форму, адрес и часы.
- Подписка: два любых сорта, выгоду по цене не обещаем.
- Телефон: коды 25, 29, 33, 44 и минский 17; повторная заявка с тем же номером за 10 минут не создаёт запись.
- Фото стоковые (Unsplash), авторы в подвале.
- Оператор «Кварта», Минск, ул. Короля, 9; срок хранения заявок 12 месяцев. Текст политики — черновик, **автор не юрист**; нужен юрист и e-mail для отзыва согласия.
- Хранилище Neon: на Render free файлы не сохраняются; дедупликация — замок на номер в транзакции (`docs/storage.md`).

## Не сделано
- Мягкая маска телефона и требование буквы в имени — не делали (наработка в локальной ветке, в main нет).
- Сообщения в Telegram-чате по сроку хранения удаляются вручную; удаление из базы — `npm run db:purge`, без расписания.
- Нет ограничения частоты запросов, от ботов только скрытое поле.
- Размытие шапки и анимации проверены эмуляцией в Chrome, не на реальном телефоне.
- UptimeRobot выключить не позже 31.10.
